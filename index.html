Exploration vs exploitation

Exploitation re-uses what the colony already knows: a high α makes ants follow strong trails; a high β makes them greedily take the nearest node.

Exploration keeps trying alternatives: lower α, larger ρ (faster forgetting) and the randomness of roulette-wheel selection let ants sample new edges.

Too much exploitation → stagnation (every ant builds the same, possibly sub-optimal tour). Too much exploration → slow or no convergence. Try α = 5, β = 0 versus α = 0, β = 5.

TSP ≠ shortest path

This lab (TSP): find a closed tour that visits every node exactly once and returns to the start. Solution = permutation of nodes. Exact solution is NP-hard; we verify small instances with Held–Karp dynamic programming.

Mumbai lab (shortest path): go from one origin to one destination; intermediate junctions are optional. Solution = simple path. Solvable exactly in polynomial time by Dijkstra, which we use as the reference.

Equations used here

$$P_{ij}^k=\frac{\tau_{ij}^{\alpha}\,\eta_{ij}^{\beta}}{\sum_{l\in N_i^k}\tau_{il}^{\alpha}\,\eta_{il}^{\beta}},\quad \eta_{ij}=\frac{1}{d_{ij}}$$
$$\tau_{ij}\leftarrow(1-\rho)\,\tau_{ij}+\sum_{k=1}^{m}\Delta\tau_{ij}^{k},\quad \Delta\tau_{ij}^{k}=\frac{Q}{L_k}$$

\(N_i^k\): unvisited nodes of ant \(k\). Initial \(\tau_0=m/C^{nn}\) (nearest-neighbour tour length), \(Q=1\). Distances are in canvas units.

1. Ant System for the Travelling Salesperson Problem

Each of \(m\) ants starts at a random node and repeatedly moves from node \(i\) to an unvisited node \(j\) with probability

$$P_{ij}^k=\frac{\tau_{ij}^{\alpha}\,\eta_{ij}^{\beta}}{\sum_{l\in N_i^k}\tau_{il}^{\alpha}\,\eta_{il}^{\beta}},\qquad \eta_{ij}=\frac{1}{d_{ij}}$$

where \(N_i^k\) is the set of nodes ant \(k\) has not yet visited. When all \(m\) tours are complete, every edge evaporates and each ant deposits pheromone inversely proportional to its tour length:

$$\tau_{ij}\leftarrow(1-\rho)\,\tau_{ij}+\sum_{k=1}^{m}\Delta\tau_{ij}^{k},\qquad \Delta\tau_{ij}^{k}=\begin{cases}Q/L_k & (i,j)\in T_k\\0&\text{otherwise}\end{cases}$$
  • Initialisation: \(\tau_0=m/C^{nn}\), with \(C^{nn}\) the nearest-neighbour tour length (Dorigo & Stützle, 2004); \(Q=1\).
  • Numerics: probabilities are computed in log-space with the log-sum-exp trick, so large α/β cannot overflow; distances are floored at \(10^{-9}\) so \(\eta\) is always finite; τ is guarded against underflow.
  • Best solutions: the best tour of every iteration and the best-so-far tour are both tracked; the convergence chart plots best-so-far, iteration-best and the average tour of all ants.
  • Ground truth: for \(n\le 15\) the exact optimum is computed with Held–Karp dynamic programming, \(O(n^2 2^n)\), and the gap \((L^*_{ACO}-L_{opt})/L_{opt}\) is shown. For the circle preset the optimum is the polygon perimeter.

2. Exploration vs exploitation

Exploitation concentrates search around what is already known to be good: large α (follow trails) or large β (greedy nearest choice). Exploration samples alternatives: small α, larger ρ (faster forgetting), and the stochastic roulette wheel. Pure exploitation causes stagnation, where all ants construct the same tour; pure exploration (α = β = 0) is a random search. ACO's performance depends on balancing the two.

3. ACO-inspired antivirus prioritisation (Lab 2)

This is an ACO-inspired adaptation, not a canonical ACO formula and not a real antivirus. Four quantities are kept separate:

QuantityMeaningUsed for
Evidence \(x=(s,b,a)\)Noisy observations from one simulated deep scan: signature match, behavioural anomaly, suspicious attributes, each in [0,1] with Gaussian noise σ = 0.2 (clipped).Risk estimate
Risk \(\hat R\)\(\hat R = w_1\bar s + w_2\bar b + w_3\bar a\), weights (0.45, 0.35, 0.20) normalised to sum to 1; \(\bar x\) = mean of the file's observations.Classification and deposit size
Pheromone τOptimisation signal: where the colony should look next.File selection only
ClassificationDecision rules on \(\hat R\) and its uncertainty margin.Reported verdict

Selection (phase 1)

$$P(f)=\frac{\tau_f^{\alpha}\,\eta_f^{\beta}}{\sum_{g\in A}\tau_g^{\alpha}\,\eta_g^{\beta}},\qquad \eta_f=\pi_f\,(1-C(n_f))$$

\(\pi_f\) is a static-triage prior from metadata alone (extension and folder), available before any deep scan; the factor \(1-C(n_f)\) lowers visibility as evidence accumulates, steering ants to where another scan is most informative. \(A\) is the Allowed set: files without a final verdict, plus confirmed threats kept under monitoring. Within one iteration ants choose distinct files.

Deposit and evaporation (phase 4)

$$\Delta\tau_f = Q\,(\varepsilon+\hat R_f)\,C(n_f),\qquad C(n)=\frac{n}{n+\kappa},\qquad \tau_f\leftarrow \mathrm{clip}\big((1-\rho)\tau_f+\textstyle\sum\Delta\tau_f,\;\tau_{min},\tau_{max}\big)$$

with \(Q=1,\ \varepsilon=0.05,\ \kappa=2,\ \tau_{min}=0.05,\ \tau_{max}=6\) (MAX–MIN bounds, Stützle & Hoos 2000). Files never investigated keep a neutral baseline \(\tau_0=0.2\) — they have no trail yet. The bounds keep τ finite; repeated investigation cannot grow it without limit.

Classification (phase 6)

With margin \(m_n = z\,\sigma_R/\sqrt{n}\), \(\sigma_R=\sigma\lVert w\rVert_2\), \(z=1.645\) (one-sided 95 %):

  • Malicious if \(\hat R-m_n\ge\theta_m\) (confirmed).
  • Clean if \(\hat R+m_n<\theta_s\).
  • Suspicious if \(\hat R\ge\theta_s\) otherwise (final "flag for review" once \(\hat R+m_n<\theta_m\)).
  • Inconclusive otherwise; after the evidence budget (default 5 scans) the point estimate decides between suspicious and clean — never malicious.

Pheromone does not appear in any rule above: a file can only be confirmed malicious by its evidence.

Scenarios

Normal: 46 benign files. Suspicious: benign files including 5 "grey" ones (unsigned installers, macro sheets, packed tools) with elevated behaviour/attribute features — tests false positives. Infected: 3 grey files, 2 known-signature samples and 1 zero-day-like sample (no signature, strong behaviour). The zero-day sample usually ends as suspicious, producing an honest false negative at default thresholds.

4. Road routing with ACO and Dijkstra (Lab 3)

The objective is a single-pair shortest path (not a tour). Each ant walks from the origin; at junction \(i\) it chooses an outgoing road \((i,j)\) with

$$P_{ij}=\frac{\tau_{ij}^{\alpha}\,\eta_{ij}^{\beta}}{\sum_{l\in A_i}\tau_{il}^{\alpha}\,\eta_{il}^{\beta}},\qquad \eta_{ij}=\frac{1}{\max\big(0,\;c_{ij}+h(j)-h(i)\big)+\delta}$$

\(c_{ij}\) is the edge cost under the selected objective, \(h\) a straight-line estimate of the remaining cost (for time: straight-line distance at the network's length-weighted mean free-flow speed), and \(\delta\) a quarter of the mean edge cost. The denominator is the A*-style reduced cost — the detour a road adds compared with heading straight to the destination. \(h\) only shapes visibility; it never prunes, and Dijkstra does not use it. Without goal-directed visibility, ants on a graph with thousands of junctions almost never reach the destination.

Allowed set \(A_i\): roads to junctions the ant has not visited. Because half the junctions sit on one-way carriageways, an ant may become boxed in; it may then revisit junctions with a strong penalty instead of being abandoned. On arrival, cycles are erased from the walk (loop elimination, as in AntNet), so every deposited route is a simple connected path. Successful ants deposit \(Q/L_k\); every road evaporates by ρ.

  • Distance objective: \(c_{ij}\) = road length (m).
  • Time objective: \(c_{ij}\) = length / free-flow speed × congestion multiplier (s).
  • Dijkstra runs on the identical graph with the identical cost function; for non-negative costs it returns the exact optimum and serves as the reference. When congestion changes, both are recomputed; ACO keeps its pheromone and adapts, and its stored best route is re-priced under the new costs.

5. Datasets

  • Mumbai roads: OpenStreetMap ways tagged highway=motorway|trunk|primary|secondary and their *_link roads in the bounding box 18.89–19.27 °N, 72.77–73.03 °E, downloaded through the Overpass API. Ways are split at junctions; one-way rules follow OSM tags; only the largest strongly connected component is kept so every origin can reach every destination. Data © OpenStreetMap contributors, ODbL 1.0. Build script: tools/build-mumbai-graph.mjs.
  • Basemap: CARTO "Dark Matter" raster tiles (© OpenStreetMap contributors, © CARTO), free for non-commercial use with attribution. If tiles fail to load, the road graph still renders from the bundled data.
  • Locality list: approximate locality centres, snapped to the nearest graph junction (snap distance is displayed).
  • Antivirus files: fully synthetic, generated from a seed; ground truth is known by construction.

6. Evaluation metrics

  • TSP: best-so-far length, iteration best, average, gap to Held–Karp optimum.
  • Antivirus: confusion matrix against ground truth (positive = classified malicious); precision \(TP/(TP+FP)\), recall \(TP/(TP+FN)\), \(F_1\). When a denominator is zero the metric is reported as undefined, not as 0 % or 100 %. Simulated cost units and a head-to-head comparison against a uniform-random scheduler on the same seed.
  • Routing: ACO best vs Dijkstra optimum under the chosen objective, both distance and time for each route, relative gap, iteration count, fraction of ants reaching the destination, and measured compute time.

7. Limitations

  • ACO is a stochastic heuristic: no guarantee of optimality; results depend on parameters and seed.
  • The road graph covers major roads only; turn restrictions, signals, tolls and local streets are not modelled. Speeds are free-flow assumptions, congestion is simulated, and no real-time traffic is used.
  • The antivirus lab models scheduling of investigations, not detection technology. Feature distributions, weights and thresholds are illustrative choices, not values learned from malware data.
  • Browser timings vary between machines and include JavaScript overhead; they are indicative only.

8. Verification

The algorithm core (js/core/) has no DOM dependency and is covered by automated tests (npm test): valid tours and paths, finite non-negative pheromone, evaporation behaviour, α/β influence, Held–Karp exactness, Dijkstra vs brute force, ACO path connectivity, congestion changing routes, metrics recomputation and threshold effects. A browser end-to-end script exercises every control.
